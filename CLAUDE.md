# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build & Development

```bash
# Install dependencies (requires Bun)
bun install

# Development mode (hot reload)
bun dev

# Build production bundle
bun run build          # bun build + post-build patch

# Type-check only (no emit)
bun run typecheck      # tsc -p ./ --noEmit

# Compile to standalone binary (macOS ARM64)
bun run sfe
```

**Runtime:** Bun (v1.3.13+). The project uses `bun build` to produce `bundle/dscode.js` (target: node), then a post-build script replaces `"react-devtools-core"` with `"fs"` in the bundle to avoid shipping devtools in the CLI.

The entry point for development is `index.tsx`. The binary is declared as `"dscode": "bundle/dscode.js"`.

## Architecture

**dscode (ONECODER)** is an interactive terminal AI coding agent — a Claude Code / Cursor-like CLI. It renders with **Ink** (React for terminals), uses **Zustand + Immer** for state, and communicates with LLMs via the **OpenAI Node SDK** (OpenAI-compatible API).

### Startup flow
1. `index.tsx` — catches uncaught errors, initializes the `~/.one-coder/` storage dir, creates the Zustand store with `Base` config (cwd, version, paths), then renders `<App />` via Ink.
2. `src/App.tsx` — vertical stack: `<History />` (scrollable conversation), `<Approval />` (tool permission dialogs), `<TextInputWithPrompts />` (user input with slash-command suggestions), `<LoadingBar />`, `<StatusBar />`, `<ExitHandler />`.

### Core agent loop (`src/agent/`)
- `src/agent/src/core/index.ts` → class `Core` — thin wrapper over `new OpenAI()` client. Registers tools and tool executors. `stream()` is an async generator yielding `StreamEvent` types (`text-delta`, `reasoning-delta`, `tool-call-delta`, `finish`).
- `src/agent/src/agents/codeAgent.ts` → `codeAgent()` factory — creates a `Core` instance pre-loaded with all tools (`ls`, `read`, `write`, `edit`, `glob`, `bash`, `todoRead/todoWrite`, `askUserQuestion`, `skill`) and the code agent system prompt (generated by `src/agent/src/prompts/codeAgentSystem.ts`).

### State (`src/store/`)
Zustand store sliced into domains, each with a `stateCreator` function:

| File | Key responsibilities |
|---|---|
| `store/bar.ts` | UI status: thinking mode (`off/high/max`), agent mode (`agent/yolo`), token usage, session ID, exit state, resume mode |
| `store/agent.ts` | The central agent loop. `sendMessage()` pushes user msg, calls `runLoop()`. `runLoop()` streams LLM response, accumulates text/reasoning/tool calls, handles tool approval flow and background task injection. UIMessages drive the conversation display. |
| `store/history.ts` | `staticKey` for forcing re-renders when resetting sessions |
| `store/approval.ts` | Tool approval UX — `requestApproval()` and `requestAnswer()` block on user decision |
| `store/config.ts` | Current model config (name, apiKey, baseURL) |
| `store/userConfig.ts` | User settings persisted to `~/.one-coder/user-config.json` |
| `store/messageHistory.ts` | Chat history for /resume |

State is persisted via `zustand/middleware/persist` with custom JSON storage to the user config file. Only `userConfig`, `thinkingMode`, and `agentMode` survive restarts.

### Agent modes
- **agent** (standard) — tools in `ApprovalCategory.WRITE` or `COMMAND` require user confirmation each time (with "agree for all session" shortcut).
- **yolo** — all tools execute without prompting.

### Tool system (`src/agent/src/tools/`)
Each tool implements the `ITool` interface: `name`, `schema` (OpenAI function definition), `approval` ({ category, requiresApproval }), and `executor(input, context, userInput)`. Tool executors return `{ payload: { llmContent }, returnDisplay }`.

The approval categories are defined in `src/agent/src/utils/constants.ts`: `WRITE`, `COMMAND`, `ASK`.

### Slash commands (`src/commands/`)
Commands match on `/name` prefix. Registered in `CommandRegistry`:
- `/config` — configure model (API key, base URL, model name)
- `/model` — select model
- `/new` — start a fresh session
- `/resume` — load a past session from logs
- `/init` — generate CLAUDE.md-style project context
- `/onedesign`, `/onesave-design`, `/onewrite-plan`, `/oneexecute-plan` — design/plan workflow
- `/exit`, `/help`

### Sessions & Logging
- **SessionManager** (`src/session/SessionManager.ts`) — scans `~/.one-coder/logs/YYYY-MM-DD/*.jsonl`, parses session files into `ModelMessage[]` + `UIMessage[]` for replay.
- **MessageLogger** (`src/logger/index.ts`) — appends JSONL lines (`{ t, mm, returnDisplay }`) per conversation turn. Crash logs go to `~/.one-coder/logs/crashes/`.

### Skills (`src/skills/`)
`SkillsManager` reads `SKILL.md` files from the project's `.agents/skills/<name>/` directories, parses YAML-like frontmatter for name/description, and injects skill summaries into the system prompt.

### Theme & rendering (`src/themes/`, `src/components/`)
Syntax highlighting uses `lowlight` + custom theme definitions. `themeManager` singleton in `src/themes/theme-manager.ts`. `TextItem` delegates to sub-renderers:
- `UserText.tsx`, `AssistantText.tsx` (markdown via `MarkdownDisplay.tsx`)
- `ThinkingBlock.tsx` (collapsible reasoning content)
- `ToolRender.tsx` (per-tool-type output formatting, e.g. diff view for edits)

### Key utilities
- `src/utils/modelConfig.ts` — maps model names to provider configs (API keys, base URLs)
- `src/utils/platform.ts` — runtime detection (CLI vs browser)
- `src/utils/resolveAtReferences.ts` — `@file` references in user input
- `src/utils/CodeColorizer.tsx` — syntax highlighting for code blocks
- `src/utils/projectContext.ts` — reads project summary files for the system prompt

## Notes
- The product is named **ONECODER** internally, though the npm package is **dscode**.
- Language is primarily Chinese (UI text, comments, system prompt language default).
- The `.agents/` and `.AGENTS.md` patterns are in `.gitignore` — skills and project description files are local-only.
